# Демо-стенд demo.vizhu.su

Временная копия прода для демонстрации. На нём работают все фичи прода, но:

- **своя БД и redis**: сносятся одной командой, прод не трогают;
- **вход**: звонок с кодом уходит как обычно, а если он не дошёл, принимается
  запасной код `DEMO_OTP_CODE` (по умолчанию `8153`);
- **фронт собран в демо-режиме**: перед вводом номера открывается экран
  «Это демо-версия», в профиле висит плашка про удаление данных.

## Как устроено

```
интернет ─► vizhu_nginx (прод) ──── сеть shared-web ────┐
              conf.d/demo.vizhu.su.conf                  │
                                        ┌────────────────┴──────────────┐
                                        │  compose-проект vizhu-demo    │
                                        │  vizhu_demo_front             │
                                        │  vizhu_demo_api ──┐           │
                                        │     сеть vizhu_demo_net       │
                                        │  vizhu_demo_ai / _postgres / _redis
                                        └───────────────────────────────┘
vizhu_demo_api ─► https://rtc.vizhu.su (LiveKit прода, по публичному адресу)
```

- Отдельный compose-проект (`name: vizhu-demo`): свои контейнеры, сеть и тома
  `vizhu_demo_*`. `docker compose` из `infra/` о нём не знает и наоборот.
- В `shared-web` включены только `demo-front` и `demo-api`: туда смотрит
  прод-nginx. БД, redis и ai сидят во внутренней `vizhu_demo_net`.
- Образы собираются на сервере из исходников текущего checkout'а. Регистр и CI
  не участвуют.
- Своими у стенда сделаны `POSTGRES_PASSWORD` и `JWT_SECRET`: токен с прода на демо
  не пройдёт, и наоборот. Ключи SMSC, GigaChat, Yandex, LiveKit и Postbox те же,
  что на проде.
- Матчинг волонтёров свой, в памяти `demo-api`. С демо можно дозвониться только до
  волонтёра, который тоже сидит на демо. Комнаты LiveKit называются
  `call_<uuid>`, поэтому с продовыми не пересекаются.
- Если стенд не запущен, nginx отдаёт заглушку 503, а сам прод-nginx не падает:
  апстримы в конфиге заданы переменными.

## Запуск

Предусловия: DNS `demo.vizhu.su` указывает на сервер, сертификат лежит в
`/etc/letsencrypt/live/demo.vizhu.su/` тома certbot, прод поднят.

1. Смержить ветку с демо в `main`. Это нужно обязательно: деплой CI делает
   `git checkout -B main` и иначе при следующем деплое уберёт файлы стенда
   и nginx-конфиг из рабочей копии. Проду этот код не мешает: всё демо-поведение
   спрятано за переменными, которых на проде нет.
2. На сервере:

   ```bash
   cd ~/vizhu/infra/demo
   ./demo.sh up
   ```

   Первый запуск сам создаст `.env`: ключи возьмёт из `infra/.env`, пароль БД
   и JWT сгенерирует. Потом соберёт образы, дождётся healthcheck'ов,
   проверит конфиг через `nginx -t` и перечитает прод-nginx.

Обновить стенд после новых коммитов: `git pull` (или деплой CI), затем снова
`./demo.sh up`. Сам CI демо не пересобирает.

| Команда                   | Что делает                      |
| ------------------------- | ------------------------------- |
| `./demo.sh up`            | собрать и поднять / обновить    |
| `./demo.sh stop`          | остановить, данные сохраняются  |
| `./demo.sh ps`            | статус                          |
| `./demo.sh logs demo-api` | логи сервиса (без имени — всех) |
| `./demo.sh destroy`       | снести всё, см. ниже            |

## Снос

```bash
cd ~/vizhu/infra/demo && ./demo.sh destroy
```

Попросит ввести `demo` и удалит контейнеры, сеть, **тома с данными**, собранные
образы и `.env`. Прод при этом не затрагивается.

Потом одним коммитом в `main` убрать инфраструктуру:

```bash
git rm -r infra/demo infra/nginx/conf.d/demo.vizhu.su.conf
```

После деплоя выполнить `docker exec vizhu_nginx nginx -s reload`.

Код под флагами можно оставить: без переменных он не срабатывает. Если хочется
вычистить и его:

- `api/src/modules/auth/auth.service.ts`: геттер `demoCode` и его использование,
  плюс тесты в `auth.service.spec.ts`;
- `front/.env.demo`, скрипт `build:demo` в `package.json`, `ARG` в `front/Dockerfile`,
  `!.env.demo` в `front/.dockerignore`, режим `demo` в `vite.config.ts`;
- `front/src/shared/config/env.ts`: `isDemo` и `demoOtpCode` (и типы в `vite-env.d.ts`);
- `front/src/pages/DemoNoticePage`, роут `auth/demo` в `app/router.tsx`, ветка
  в `StartPage`;
- `front/src/pages/ProfilePage/ui/DemoNotice.tsx` и его вызовы.

## Если что-то не так

- **`nginx -t` падает на сертификате**: сертификата нет в томе certbot. Выпустить
  его, затем снова `./demo.sh up`. Прод-nginx при этом продолжает работать на старом
  конфиге.
- **Звонки волонтёрам не соединяются, в логах `demo-api` ошибка createRoom**:
  сервер не может достучаться сам до себя по публичному адресу. Прописать
  в `.env` `LIVEKIT_HOST=http://<внутренний IP сервера>:7880` (если порт 7880
  LiveKit опубликован на хосте) или подключить `demo-api` к сети прода
  `infra_backend_net` и указать `LIVEKIT_HOST=http://livekit:7880`.
- **Код не приходит**: так и задумано, вводить `8153`. В логах `demo-api` будет
  видно, ушёл ли звонок.
